# Release

The release is driven by the tag: pushing a `v<version>` tag triggers the
GitHub Actions workflow in `.github/workflows/release.yml` (generated by
[cargo-dist](https://github.com/axodotdev/cargo-dist)), which builds
the binaries for all the supported targets and creates the GitHub Release with
the notes taken from `CHANGELOG.md`.

Only the version bump is needed in preparation. `default.nix` reads the version
from `Cargo.toml`, so it does not need to be updated manually.

## Prerequisites

- A clean working tree on `main`, with everything pushed to GitHub.
- `cargo-dist` installed if you want to regenerate the workflows
  (`nix develop` provides it, or `cargo install cargo-dist`).
- A crates.io token configured for `cargo publish`.

## Steps

1. Bump the version in `Cargo.toml` (for example `version = "1.0.17"`).

2. Add a `## v1.0.17` section at the top of `CHANGELOG.md`. This is the heading
   format that cargo-dist uses to build the GitHub Release notes.

3. Rebuild so that `Cargo.lock` carries the new version:

   ```bash
   cargo build
   ```

4. Commit and push to `main`:

   ```bash
   git add -A
   git commit -m "chore: bump version to 1.0.17"
   git push origin main
   ```

5. Create and push the tag:

   ```bash
   git tag v1.0.17
   git push origin v1.0.17
   ```

   This triggers the release workflow. Check that it succeeds with:

   ```bash
   gh run list --limit 3
   gh release view v1.0.17
   ```

6. Publish to crates.io **after** the GitHub Release exists:

   ```bash
   cargo publish
   ```

   `cargo publish` requires a clean working tree and a `Cargo.lock` whose
   `ateam` version matches `Cargo.toml`. Publishing first would ship a version
   whose tag does not exist yet.

7. Optional: regenerate the macOS Homebrew formula snippet with the new
   checksums:

   ```bash
   ./release-apple-darwin.sh 1.0.17
   ```

## Notes

- The `release` skill in `.agents/skills/release/SKILL.md` automates steps 2-6
  once the version bump has been committed and pushed.
- `cargo publish` fails with "crate ateam@<version> already exists" if that
  version was already published. Bump the version instead of retrying.
